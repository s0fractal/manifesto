## 1. Обґрунтування (Rationale & Problem Statement)

### 1.1. Проблема сучасної взаємодії AI-агентів
Сучасний інтернет та агентні пайплайни стикаються з трьома критичними кризами:
1. **Епістемічна евтрофікація ($\mu \approx 2\text{–}3$):** Агенти генерують неперевірений текст швидше, ніж люди чи інші моделі встигають його аудіювати. Перевірка неформального тексту розгалужується і не сходиться сама по собі (Теорема `RVB-0.1`).
2. **Сліпе підлабузництво та отруєння висновків (Taint Propagation):** Агенти сліпо довіряють одруківкам і галюцинаціям людини-оператора або сусіднього агента, перетворюючи одну хибну передумову на ланцюг отруєних висновків (доведено в експерименті `EXP-SSD-STREAM`).
3. **Ілюзія безпеки через підпис логів:** Існуючі стандарти (IETF VAC, in-toto, Sigstore) підписують *транскрипти* («модель справді сказала X»), але не здатні перевірити *істинність фактів усередині X*.

### 1.2. Доведена інженерна перевага нашого стека
В експериментах `manifesto` доведено:
* **$\mu = 0$ для розрахованих претензій:** Машинно-розраховані твердження на базі Σ-GLYPH та CAS-сховища замикають перевірку детерміновано.
* **Принцип AIE (Addressing Is Equality):** Порівняння адрес канонічних нормальних форм здешевлює розрахунок рівності в $100\,000\times$ порівняно з внутрішньомовними предикатами (601 ATP проти >59M ATP).
* **Працюючий прототип ґейта:** `tools/settle_gate.py` у проведених експериментах зловив 100% хибних претензій **серед розмічених претензій підтримуваних класів** (4/4 у SSD-DEMO, 28/28 в індекс-аудиті) та запечатав корекційний цикл у валідний Warrant Evidence Pack. *(Скоуп-правка за OAH-дисципліною, Claude: нерозмічений текст мембрана не бачить — це фальсифікатор F2 у SSD-PLAN, і саме тому Phase 2 передбачає екстракцію претензій з вільного тексту.)*

## 3. Специфікація інтерфейсу та класів претензій

### 3.1. Підтримувані класи тверджень (Claim Classes v1.0)
Генератор розмічає перевірні твердження синтаксисом `⟦клас: вміст⟧`:
1. `⟦arith: A op B = C⟧` — арифметика над цілими числами, що розраховується на детермінованому ядрі Σ-GLYPH за фіксований $ATP$.
2. `⟦count: /regex/ in <шлях> = N⟧` — перевірна кількість входжень у локальні файли чи сховище.
3. `⟦cite: "цитата" in <шлях>⟧` — перевірка точної дослівності цитати (захист від вигаданих цитат).
4. `⟦sha256: <шлях> = <префікс>⟧` — перевірка криптографічної ідентичності файлу/блобу.
5. `⟦mono: c1, c2, ... ev i, j⟧` — перевірка монотонності впевненості та відсутності неліцензованих стрибків логіки (інваріант нотатки `0030`).

### 3.2. Вихідні бейджі результату
* ⚓ **`settled`** — претензія розрахована на байтах сховища, є істинною, супроводжується хешем нормальної форми та витраченим $ATP$.
* ✗ **`REFUTED`** — претензія розрахована і виявилася хибною. Містить фактичне виправлене значення (постачальник ремонту).
* ◇ **`unsettled` / `speculative`** — твердження не підлягає механічному розрахунку (думка, метафора, гіпотеза), чесно носить свій тип і не маскується під факт.

## 4. Конкретні етапи реалізації (Roadmap)

### Етап 1: Автономний CLI та MCP-сервер (`settle-mcp`) — ✅ ПРАЦЮЄ (2026-08-30, v0.1)
* Реалізовано: `tools/settle_mcp.py` — MCP stdio-сервер (newline-delimited JSON-RPC 2.0, **нуль залежностей**, двигун — уже виміряні settle_gate + glyphlib + taint_check).
* Інструменти (протестовано end-to-end через справжній stdio-цикл):
  * `settle_text(markdown) -> { settled_text, receipt }` — тест: `74+1=75` ⚓ на Σ-GLYPH за 3 893 ATP; `6*7=41` ✗; вигадана цитата ✗; нерозмічений текст неторканий.
  * `verify_receipt(markdown, receipt) -> { match, hashes }` — верифікація = replay: перерозрахунок і побайтове порівняння; roundtrip-тест: match=true.
  * `check_taint(receipts[]) -> taint_report` — тест на квитанціях EXP-SSD-STREAM: 6/7 отруєних знайдено, poison set [5,14,21,35].
* Підключення: `{"mcpServers":{"settle":{"command":"python3","args":["<repo>/tools/settle_mcp.py"]}}}` — Claude Desktop / Cursor / Antigravity / будь-який MCP-клієнт.
* Лишилось з Етапу 1: упаковка в pip-пакет (setup/pyproject), винесення шляху репозиторію в конфіг.

### Етап 2: Автоматичний корекційний стрімінг-цикл
* Якщо `settle-mcp` виявляє ✗ `REFUTED`, він не просто видає помилку користувачу, а автоматично повертає моделі-генератору фактичні виправлені байти для миттєвого виправлення до фінального показу (перевірено в `SSD-DEMO-0.2`: 100% ліквідація галюцинацій).

### Етап 3: Запечатування у Warrant Pack
* Автоматична генерація підписаного файлу `warrant-evidence-pack.json` з Ed25519-підписом на кожен завершений сеанс міркувань.
* Можливість передачі квитанції іншому агенту, який валідує всі факти сесії за ціну повторного розрахунку квитанції (лінійно від кількості претензій, копійки ATP), без повторного виклику важкої LLM. *(Скоуп-правка, Claude: не $O(1)$ — валідація і є перерозрахунок; $O(1)$ лише порівняння хеша вже перерахованої квитанції.)*

## 5. Чіткі межі та Non-Goals (Захист від роздуття)

* **НЕ універсальний факт-чекер усього Інтернету:** `settle-mcp` не парсить загальний веб через пошуковики; він оперує **лише локальними файлами, контент-адресованими сховищами (CAS) та детермінованою математикою**.
* **НЕ LLM-суддя:** Розрахунок претензій виконується суто детермінованим кодом (Python/Σ-GLYPH/SHA-256), а не іншим недетермінованим промптом.
* **НЕ цензура уяви:** Спекулятивні та філософські думки не блокуються — вони отримують статус ◇ `speculative`, що зберігає повну свободу мислення (White Cone), захищаючи базу фактів (Black Cone).

## 6. Критерії успіху та фальсифікатори

1. **Метрика надійності:** Кількість непомічених числових або цитатних галюцинацій у розміченому тексті = **0**.
2. **Метрика швидкості:** Час розрахунку стандартного документа (10–20 претензій) $\le 100\text{ мс}$ ($< 10\,000\text{ ATP}$).
3. **Фальсифікатор (F1):** Якщо сторонній агент отримує ⚓ `settled` твердження, яке не відтворюється біт-у-біт на незалежному рантаймі — ґейт вважається скомпрометованим.
