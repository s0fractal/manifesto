# FLOW-0.3 mining — методологія (для аудитабельності, Codex §6)

**Що це:** видобуток пропозицій FLOW-примітивів із корпусу Monday, синтез якого — `drafts/FLOW-0.3-CANDIDATES.md`. Codex §6 слушно вимагає зберегти промпти, ідентичності моделей і процедуру синтезу, інакше методологічне твердження неможливо аудитувати.

## Читачі

Три паралельні агенти типу **Explore** (read-only), запущені Claude (Fable 5) як оркестратором, 2026-08-31. Explore-агенти успадковують модель головного циклу сесії (Fable 5) — тобто **вся lineage спільна**, що прямо обмежує незалежність (§6 рев'ю: рекурентність ≠ валідація саме через це). Це не багатовендорний збір; це кілька проходів читання однією lineage.

## Рубрика (ідентична всім трьом)

Класифікувати кожну пропозицію примітива в один кошик за загартованим стандартом репозиторію (**примітив мусить щось забороняти**; "типізація нетипійовного" — окремо):
- **ADOPT** — забороняє щось / має truth-conditions / не у FLOW / не словник.
- **OVERREACH** — crisp-тип на несумірному; з поясненням чому.
- **ALREADY** — рестейт наявного примітива FLOW.

Плюс: позначити все, що чіпляє відкриті борги D5/D16, D17, D15/D18, Evidence_t.

## Обмеження (несучі)

1. **Спільна lineage** → рекурентність між нотами й між читачами не є незалежним підтвердженням (нульовий кредит валідації).
2. **Сирі виходи** живуть у транскриптах цієї сесії (task-нотифікації трьох агентів); тут збережено лише синтез і цей опис. Повний JSONL — у session-каталозі.
3. Синтез — суб'єктивний крок одного агента (Fable 5); його завищення ("convergence") зловив аудит Codex — доказ, що синтез сам потребує аудиту, який і відбувся.
4. Джерела видобувачів вибірково звірені ґейтом (кожна цитована нота містить свій матеріал: 0025→15 impossibility-термів, 0044→485 "viab", 0042→36 path-depend, 0045→172 infrastructure, 0070→140 admissib/commons) — це спростовує *галюцинацію джерела*, не валідує *зміст* пропозицій.
