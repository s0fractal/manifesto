# ts-sigma — TS/Deno identity layer for Σ-GLYPH (DISCOVERY PROTOTYPE, not canonical)

> **Канонічний дім — sigma-glyph, не тут (рішення 2026-08-31).** Ця директорія — *discovery-прототип*, що доводить портовність identity-шару (7 векторів байт-збіг). Він **не для імпорту** іншими репо. Правильний шлях: TS-реалізація входить у sigma-glyph через їхній proposal/ADR-процес, ганяється проти повного 49-векторного conformance-suite там, релізиться як версіонований пакет (JSR/npm), і решта репо пінять конкретну версію — з обов'язковим CI-переганянням конформності на пінованій версії (dependency-bound-receipt логіка для залежності). Причина: проти дрейфу від референса; конформність має сенс лише у спільній гарматі; коса, не копіпаста. Пропозиція чекає тихого моменту в sigma-glyph (там активна робота). Аналіз — у коміті, що додав цю нотатку.

**Що це:** мінімальний TS/Deno порт **шару ідентичності** Σ-GLYPH Book I — канонічна серіалізація + SHA-256 node-хешування + побудова термів, **байт-у-байт сумісні з Python-референсом** (`sigma-glyph/impl/sigma_glyph.py`). Народжений із запиту оператора: верифіковні тести корисні на власному TS/Deno-стеку, і TS-sigma це розблоковує.

**Що це НЕ:** це **не** ATP-бюджетований лінивий евалуатор і воно **не редукує** терми. Редукція (eval_hash, ATP, hash-thunk машина) — окремий, більший порт, свідомо винесений у майбутнє, щоб не завищити "conformant reimplementation", якого один сеанс не доводить.

## Чому шар ідентичності сам по собі вартий

Settlement-квитанція — content-addressed. Відтворивши node-хеші, TS-стек може:
- перевірити "чи цей терм хешується в цю адресу" (verify by address);
- порівняти дві normal-form адреси — субстрат equality-by-address (AIE) — **без** повного евалуатора.

Тобто верифікація значної частини квитанцій доступна вже на цьому шарі.

## Конформність (перевірено, не заявлено)

`conformance_test.ts` пінить 7 node-хешів (I, K, S, FALSE, і три application-вузли), **звірених наживо байт-у-байт із Python-референсом 2026-08-31**. Піни детерміновані (SHA-256), тож тест самодостатній — TS-стек ганяє його без Python. Перезвірка: `deno run ts-sigma/conformance.ts` поруч із Python-емітером тих самих термів.

```
deno test ts-sigma/conformance_test.ts   # 2 passed
```

## "Верифіковний тест" — що це в цьому сенсі

Демо в `conformance_test.ts`: тест, чий **вердикт — content-addressed рівність**, а не "assert не кинув". Проходить лише якщо конструкція осідає в пінену адресу; re-executable, детермінований, μ=0 (верифікація = перерахувати хеш). Це примітив, на якому будувалась би `deno-test-sigma` / `pytest-sigma` гармата: assertion як settled address, а не як довіра до "ok".

## Межі та наступні кроки (чесно)

- **v0 — лише ідентичність.** Редукція, ATP-бюджет, exit-kinds (NF/Exhausted/Unresolved), receipt-gap — не портовано.
- **Конформність — на 7 векторах, не на повному suite.** sigma-glyph має 49 conformance vectors; тут звірено 7 identity-вузлів. Повна конформність = окрема робота і належить upstream (sigma-glyph), не сюди.
- **Lineage-застереження (правило перетину):** цей порт написаний тим самим агентом-lineage; байт-збіг із Python — сильніший за рекурентність (це виконуваний свідок ідентичності), але незалежний людський аудит серіалізації досі нуль.
- Наступне (усе **belongs upstream у sigma-glyph**, не тут): (1) TS-Store (CAS) + verify-receipt-by-address; (2) малий eager SKI-редуктор для простих NF; (3) лише потім — повна лінива ATP-машина, якщо взагалі треба. Цей прототип живить upstream-пропозицію, а не продовжується як окрема реалізація.
